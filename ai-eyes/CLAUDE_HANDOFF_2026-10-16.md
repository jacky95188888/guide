## 4. 技術判斷

1. **背景 Interactions API 是目前已驗證的主路線**：`POST /interactions` 建立 `background:true, store:true` 任務；取得 ID 後以 `GET /interactions/{id}` 查詢，直到 `completed`。
2. 同步影片分析 100 秒逾時屬本地 Worker 設定的停止條件；先停止把同步分析當主路線。
3. 503 高需求曾發生，但此次截圖中 ①②③⑤ 均有成功證據；不要把 401、503、100 秒逾時混為同一根因。
4. 手機版目前輸出大段 JSON、含跳脫字元 `\\n`，閱讀體驗差；需報告視圖與可展開診斷區。
5. 背景任務 ID 應可恢復；查詢 429/503 可有限次退避重試，**不能在 POST 建立背景任務逾時時盲目重送，避免重複任務／費用**。

## 5. V3.4 工作順序（只做必要變更）

### P0：保護成功版本
- 先取得 Cloudflare **實際部署的完整 Worker 原始碼**，存成不可覆蓋的 baseline；若只能取得聊天中的 V3.3，標示「未證實與線上一致」。
- 先核對 `/health` 版本；不要動現有 Secrets、模型設定、路由或其他 Workers。
- 建立獨立候選版本；未驗證前禁止正式發布。

### P1：穩定性
- 背景模式作為 ⑤ 及官方範例預設；同步模式改為診斷用途。
- `/result` 的暫時性 429/503、網路錯誤採最多 3 次、有上限的退避重試；永久性 400/401/403 直接顯示。
- `completed` 才算成功；`queued/in_progress` 持續輪詢；`failed/cancelled/unknown` 停止並呈現原因。
- 使用者關閉手機頁面後可用任務 ID 恢復；本地只保存任務 ID／影片網址／模型／時間，不保存 API Key 或密碼。
- 區分 Worker HTTP 狀態與 Google `upstreamStatus`，避免假成功。

### P2：報告 UX
- 顯示：一段式總結、帶時間軸事件、畫面／人物動作／聲音／對白／鏡頭與剪輯／情緒與敘事效果／可驗證細節／不確定性。
- 預設呈現正常換行的繁中報告，JSON 放在「展開技術紀錄」。
- 不可把模型推測的「無音樂」「精確台詞」「物件顏色」當成已人工驗證。

### P3：影片理解驗收
- 以使用者自己的影片，挑 3 個帶時間碼的事實對照原片：①畫面物件／人物 ②原聲對白／聲音 ③鏡頭切換／動作。
- 記錄「正確／部分正確／錯誤／無法核對」及證據；再評估是否能可靠分析情緒、敘事、剪輯技法。
- 不要求 Claude 僅靠搜尋影片標題或字幕就宣稱看完影片。
